## ERRORES COMUNES

**LOCUTOR:** Primero hablemos de los errores comunes. Todos nos equivocamos. Por ello, te mostramos los cinco errores más comunes:

* Primero, olvidar cerrar una etiqueta.
* Segundo, olvidar el punto y coma en CSS.
* Tercero, escribir mal el nombre de una clase.
* Cuarto, poner mal el enlace de una imagen.
* Quinto, no escribir el `alt`.

Un consejo: si la imagen no aparece, casi siempre el problema es el enlace en `src`.

## MINI PRÁCTICA: ¡CAZA 3 ERRORES!

**LOCUTOR:** Ahora pasemos a una práctica. Abran el enlace del código roto y encuentren tres errores. Pueden pausar el video para que sí tengan tiempo. Una vez se cumple el tiempo, volvamos a la lección.

**EN PANTALLA:** Se escribe cada ejercicio en CodePen, se muestra el resultado, aparece una cuenta regresiva de 3 segundos y se corrige el error (la línea con error en rojo y la corrección en verde).

* **Ejercicio 1**: falta cerrar `</h1>`.
* **Ejercicio 2**: la imagen no tiene `alt` y su enlace `src` no existe.
* **Ejercicio 3**: la clase está mal escrita (`.perfl` en vez de `.perfil`) y falta el punto y coma después de `white`.

**LOCUTOR:** Perfecto. Ahora, ¿cuál de estos errores les pasó a ustedes hoy?

## BUENAS PRÁCTICAS

**LOCUTOR:** Ahora, pasando con buenas prácticas. Los programadores profesionales tienen hábitos:

* Dejan sangría, o sea, espacios al escribir, para que el código sea legible.
* Usan comentarios para dejar notas.
* Eligen nombres claros.
* Prueban después de cada cambio.
* Validan si su código es válido en el validador de W3C, que revisa si hay errores.

**EN PANTALLA:** Se pega el código de perfil en el validador de W3C y aparece el mensaje verde de que no hay errores ni advertencias.

**LOCUTOR:** A continuación, se muestran dos tipos de códigos: uno desordenado y otro ordenado. De estos, ¿tú cuál crees que sea más fácil de leer? Y ahora, ¿qué hábito te parece más útil para empezar?
